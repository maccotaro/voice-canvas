# 声のCanva (Voice Designer) — 実装仕様書

## 1. プロダクト概要

実在話者から抽出した音声パラメータをもとに、**人間が手動で声をデザインするツール**（声のCanva的UI）を作る。スライダーで直感的に声質を編集し、破綻しない範囲でリアルタイム試聴、確定した声を `reference.wav` として書き出す。書き出した wav は既存の GPT-SoVITS / RVC パイプラインの入力（参照音声）として使う。

- **最終形**: 6本程度の解釈可能なスライダーで声を無段階編集できるデザインツール
- **本MVPのゴール**: 1〜数話者を分析再合成し、6軸スライダーで編集→即試聴→reference.wav書き出しが動くこと
- **GPUは不要**（信号処理主体、CPUで完結）。neural vocoder書き出しは後段オプション。

## 2. 設計思想（重要・必読）

### 2.1 パラメータは独立に動かせない

人間音声のパラメータ（F0・フォルマント・気息・粗さ等）は強く相関する。生のWORLDパラメータを独立スライダーにすると「物理的にありえない声」が即座に作れて破綻する（例: F0だけ女性域・フォルマントだけ男性域）。

→ **対策**: 生パラメータを直接UIに出さない。意味づけされた少数の軸（下記）の裏で複数パラメータを相関連動させる。

### 2.2 軸は「解釈優先」で人手設計する（PCAをUIに出さない）

PCAで直交化すると数学的には綺麗だが、主成分が混合特徴になりユーザーに意味が伝わらない。PCA/相関分析は **内部で相関構造を担保する用途に限定**し、UIに見せる軸は人手で意味づけする。

推奨6軸（端点ラベル）:

| 軸       | 端点                 | 連動する主パラメータ                        |
| -------- | -------------------- | ------------------------------------------- |
| 体格     | 太い ⇄ 細い         | 声道長(フォルマント全体スケール) + F0       |
| 性別印象 | 男性的 ⇄ 女性的     | F0 + フォルマント                           |
| 明るさ   | 明るい ⇄ こもった   | 高域フォルマント/スペクトル傾斜(brightness) |
| 緊張     | 張った ⇄ リラックス | tension + jitter                            |
| 気息     | ハスキー ⇄ クリア   | breath(非周期成分) + HNR                    |
| 年齢印象 | 若い ⇄ 年配         | shimmer + F0安定性                          |

各軸は1本のスライダー。スライダーを動かすと、裏で複数のWORLDパラメータが相関に従って同時に変化する。

### 2.3 ガードレールはUIで吸収する

閾値超過を例外処理で弾くのではなく、**スライダーの可動域そのものを実測分布の ±2σ に物理的に制限**する。ユーザーが破綻領域に到達できなければ、破綻則の例外処理は基本的に不要になる。

## 3. 技術スタック

| 用途                                 | ライブラリ                             |
| ------------------------------------ | -------------------------------------- |
| F0/SP/AP 分析・再合成                | `pyworld`                            |
| フォルマント/jitter/shimmer/HNR 抽出 | `praat-parselmouth`                  |
| 日本語G2P（音素化）                  | `pyopenjtalk`                        |
| 音声I/O・リサンプル                  | `librosa`, `soundfile`             |
| 数値・統計・相関/PCA(内部用)         | `numpy`, `scipy`, `scikit-learn` |
| スライダーUI + 即試聴                | `gradio`                             |
| (後段オプション) 高品質書き出し      | HiFi-GAN 等 neural vocoder             |


```bash
pip install pyworld praat-parselmouth pyopenjtalk librosa soundfile scikit-learn gradio
```

- 強制アラインメント（MFA）は **MVPでは不要**。同一文・既知テキスト前提なら pyopenjtalk の音素列 + pyworld のフレーム単位F0で簡易的に対応。精度が要る段階で MFA(Montreal Forced Aligner) を後から導入。
- CPU のみで動作。Python 3.10+。

## 4. 実装ステップ（この順で作る）

### Step 0: 分析再合成の地盤確認（最優先・最初の1歩）

1. 任意の1話者のクリーンな録音 wav を読み込む
2. `pyworld` で F0 / スペクトル包絡(SP) / 非周期性(AP) を抽出
3. そのまま再合成し、原音とほぼ同等に戻ることを確認
4. **F0 を ±2半音スケーリングして再合成し、破綻しない（自然に聞こえる）ことを耳で確認**

→ これが鳴れば構想全体の地盤が確認できる。ここを最初の単体スクリプトとして必ず通すこと。

### Step 1: パラメータ抽出パイプライン

- 入力: 話者ごとの録音 wav（MVPは1〜数話者でよい）
- `pyworld`: F0, SP, AP（フレーム単位）
- `parselmouth`: フォルマント(F1〜F4), jitter, shimmer, HNR, スペクトル傾斜
- 出力: 話者ごとの特徴量を保存（npz/json）

### Step 2: 軸設計とマッピング

- 抽出した特徴量の **相関を確認**（相関行列を出力）
- §2.2 の6軸を定義し、各軸 → 複数WORLDパラメータへの変換則を実装
  - 各軸は連続値（例 -1.0〜+1.0）
  - 軸→パラメータは、相関を反映した線形（または区分線形）変換
- 各パラメータの実測分布から **±2σ の可動域** を算出し、軸の端点に対応させる
- アンカー: 各軸の端点に、実在話者の代表サンプルを据える（生成声は実在声間の補間として位置づく）

### Step 3: 再合成エンジン

- 入力: 6軸の値 + ベース話者の SP/AP 構造
- 軸 → WORLDパラメータ変換 → `pyworld.synthesize` で wav 生成
- 1文あたり数百ms〜秒で返ること（スライダー操作→即試聴のループ用）

### Step 4: Gradio UI

- 6本のスライダー（ラベルは §2.2 の端点表記、可動域は ±2σ で固定）
- 「再生」: 現在のスライダー値で再合成し、その場で試聴
- スライダー変更→即時プレビュー（WORLD即時合成）
- 「reference.wav として書き出し」ボタン

### Step 5（オプション・後段）: 高品質書き出し

- 編集中は WORLD 即時プレビュー、**確定後のみ** neural vocoder(HiFi-GAN等)で高品質レンダリング
- 2モード構成（プレビュー=WORLD / 書き出し=neural）

## 5. 既知の制約（実装時に踏まえる）

- **WORLDボコーダーの自然性上限**: 同一文・クリーン録音で MOS 4.0前後が天井。無声摩擦音・破裂音・高F0・気息成分で劣化しやすい。プレビュー用途では許容範囲。本番品質が要る場合は Step 5 の neural vocoder へ。
- **AP（非周期成分=気息）操作は荒い**: 「ハスキー⇄クリア」軸はやりすぎると別人化・機械臭が出やすい。可動域を保守的に。
- **話者数が少ない**（MVP想定 1〜数話者）: 厳密なσ推定には不足。MVPでは「軸の端点アンカー」と「補間」用途と割り切る。多変量の相関構造を安定推定したい段階で話者を増やす（性別・年齢で層化推奨）。

## 6. 成功判定（MVPのDone定義）

1. 1話者を分析再合成して原音相当に戻る
2. F0 ±2半音で破綻しない
3. 6本スライダーで編集→即試聴ができる
4. 各スライダーが**意図通りに知覚される**（「太く」で実際に太く聞こえる）← ここが最重要の検証ポイント
5. 確定した声を reference.wav として書き出せる
6. 書き出した wav が GPT-SoVITS の参照音声として読み込める

> 注: 最初に作り込むべきはUIの見た目ではなく、**Step 2 の軸設計の妥当性**（4番）。スライダーを動かして本当に意図通り聞こえるかが、プロダクト成立の分水嶺。
